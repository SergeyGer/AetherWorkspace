# v0.4.3 — deterministic per-project test evidence

Patch release replacing heuristic TRX discovery with deterministic per-project execution, so
R1 evidence counters can no longer be distorted by duplicate/stray TRX files.

## Fixed

- **Portable suite evidence** (`tools/windows-test/Run-AetherTests.ps1`): instead of
  `dotnet test <solution>` + worktree TRX discovery, the orchestrator now:
  1. parses `AetherWorkspace.slnx` and enumerates the eight `tests/*.Tests.csproj` projects;
  2. runs each project separately with `--logger trx;LogFileName=<project>.trx` into
     `results/trx/portable/`;
  3. aggregates exactly those eight TRX files and marks the suite:
     `FAIL_HARNESS` on timeout, `FAIL_PRODUCT` on a failing project, `INCONCLUSIVE` when a
     TRX file is missing or no tests executed.
  Locally simulated collection: **8 files / 445 passed** (matches Linux and Windows CI).
- R1 evidence records the v0.4.2 control run (`20261116-094002-release-full-a5f4d6`, commit
  `d44e6ba`) — PASS, exit 0, single-monitor environment (1920×1200, 100% DPI).
- Historique of the counter issue: v0.4.1 run reported portable=664 and v0.4.2 run reported
  portable=781 against the 445 baseline; per-project suite logs always confirmed the true 445
  passed. v0.4.3 removes the heuristic entirely.
