# v0.2.0 — reliability and observability hardening

Reliability/observability step after the MVP vertical slice.

## Highlights

- Bounded per-channel queues with explicit overflow accounting, FIFO ordering, deduplication and RPC-level idempotent retry semantics.
- Heartbeat/missed-heartbeat health states, process-exit detection and bounded restart; fault injection for hung (`SIGSTOP`) and killed apps plus broker-disconnect fail-fast; crash+restart E2E.
- Offline headless mode (`--offline`) with provider health reporting and no cloud adapter construction; missing local model yields a safe error without cloud fallback.
- Rotating/retained audit storage (`--audit-max-bytes`, `--audit-files`) with verification across retained files and a continuous hash chain across process restarts (tampered persisted chains rejected fail-closed).
- Windows named-pipe client bug found by CI and fixed (stream properties set before connect); Windows test portability fixed.
- 333 automated tests; CI green on Linux and Windows (build, tests, named-pipe demo); CodeQL default setup green.
- GitHub publication: milestones, labels, 38 issues from the planning kit, wiki pages.

## Evidence

- Local: `dotnet build` Release 0 warnings; `dotnet test` 333/333; demo exit 0.
- CI: both Linux and Windows jobs green, including the Windows named-pipe reference demo.
- Benchmarks: measured IPC baseline in `docs/BENCHMARKS.md` (Linux UDS); Windows reference benchmark still pending.

## Known limitations

WPF interactive UI behaviour and visual Win32 arrangement are not automatically verified yet (UI automation is a later step). OS-level blocked-egress capture and Windows reference-machine benchmarks were not yet part of CI at this tag. No release binaries or SBOM are attached; source archives are provided by GitHub.
