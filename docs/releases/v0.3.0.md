# v0.3.0 — bounded FDC3 interoperability + reliability closure

Bounded FDC3 3.0 interoperability plus the remaining v0.2 reliability evidence.

## Highlights

- Declared, tested FDC3-aligned subset: `fdc3.instrument` and `fdc3.organization` contexts on the single `default` app channel with provenance metadata.
- Limited intent resolution (`ViewInstrument`, `ViewAnalysis`, `ViewChart`) mapping to apps that explicitly declare the intent and accept the required context type; bounded app-directory subset exposed by the broker snapshot.
- Unknown intents, context-type mismatches, unknown contexts and unapproved explicit intent targets are rejected with structured denial codes.
- Contract fixtures and a dedicated `Aether.Fdc3.Tests` suite; multi-process E2E publishes an organization context to all three sample apps and resolves intents against the real broker.
- OS-level blocked-egress evidence: Linux workflow runs inside an isolated network namespace with no external connectivity; Windows CI blocks outbound .NET traffic via Windows Firewall. Both must keep the reference workflow green with zero external egress attempts.
- Windows named-pipe IPC benchmark added to Windows CI; benchmarks methodology updated.
- WPF UI automation tests (FlaUI) added for the Windows shell (build + UI smoke/workflow evidence in Windows CI).
- `.env.example` template for future model providers (OpenAI, Google Gemini, local loopback); `.env` is git-ignored and loaded only explicitly with `--env-file`.
- Publishing: GitHub Releases for v0.1.0/v0.2.0/v0.3.0, SBOM (SPDX) and source archives attached; main-branch protection/rulesets; issue dependency links, assignees and a Kanban project.

## Evidence

- Release build 0 warnings; full test suite green locally; CI green on Linux and Windows including named-pipe demo, WPF UI automation, blocked-egress checks and Windows IPC benchmark.
- SBOM and SHA-256 checksums attached to this release.

## Known limitations

- This remains a **declared bounded FDC3 subset**, not conformance: no Desktop Agent API, user channels, intents beyond the three listed, app-directory federation or third-party FDC3 interop tests.
- WPF UI automation covers the shell smoke + reference workflow; visual Win32 arrangement/per-monitor DPI correctness still requires manual desktop verification.
- Model adapters are disabled by default; real Gemini/OpenAI/local model evaluation is v0.4 work.
- No production data, compliance claims or universal performance guarantees.
