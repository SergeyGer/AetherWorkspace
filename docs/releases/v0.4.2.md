# v0.4.2 — TRX evidence de-duplication and control-run record

Patch release hardening the local Windows 11 test-harness evidence collection after the v0.4.1
control run exposed duplicate/stray TRX over-counting.

## Fixed

- **TRX discovery** (`tools/windows-test/Run-AetherTests.ps1`): the solution collector scanned
  the whole detached worktree and could pick up duplicate or stale TRX files; the v0.4.1
  control run reported `portable=664` against the 445-test baseline. Discovery now:
  - scans only `tests/<project>/TestResults` (with a recursive fallback only when nothing is
    found there),
  - ignores TRX files older than the suite start (with a one-minute tolerance),
  - de-duplicates identical files by SHA-256 before aggregating Counters.
  Validated with a synthetic worktree containing a duplicate `bin/` copy and a stale TRX:
  only the 2 valid project files were counted (aggregate total 5).
- R1 evidence updated with the v0.4.1 control `release-full` run
  (`20261116-091552-release-full-97b9bf`, commit `4a2796e`) — PASS, exit 0.

## Evidence status

- Physical Windows 11 runs on approved SHAs: `developer-smoke`, `daily-smoke`, `release-full`
