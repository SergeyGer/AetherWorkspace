# AetherWorkspace v1.0.2 — packaged-desktop diagnostics and verification hardening

Corrective diagnostics release for the v1.0.1 clean-machine desktop run. The desktop bundle now
ships its own headless self-test and privacy-safe diagnostics collector, and WPF sample apps have
heartbeat/diagnostic logging parity.

## Status of the v1.0.1 clean-machine findings

- Windows desktop bundle download, launcher, broker handshake and WPF Shell start were **confirmed**
  on the reference Windows 11 machine; independent full-asset verification returned **VERIFY PASS**
  (desktop, headless, source, SPDX SBOM, SHA-256).
- The reference workflow opened the three real WPF sample windows, which then closed. The exact
  workflow result in that packaged run was not captured, so the release adds introspection rather
  than claiming a fix: CI now proves the real WPF sample windows survive launch, context delivery
  and the full GUI workflow when built from the repository, and the package self-test captures the
  same information for the packaged layout.

## Added / changed

- **`Test-AetherWorkflow.ps1`** in the Windows desktop bundle: starts the packaged broker with the
  WPF app registry, runs the reference command through the bundled headless shell, writes the
  structured workflow result plus a sanitized diagnostics bundle under `diagnostics/`, then stops
  the broker and test children. This makes packaged-only failures directly inspectable.
- **`Collect-Diagnostics.ps1`**: gathers process/bundle/log/result/Event Log context into a ZIP;
  deliberately excludes the endpoint handshake file (operator token) and states the synthetic-only
  privacy boundary.
- **WPF sample apps:** heartbeat loop parity with the headless samples (reduces unresponsive health
  states), global unhandled-exception logging to stderr (broker child log) and
  `%TEMP%\aether-sample-logs`, and explicit connect-failure logging.
- **`Verify-Release.ps1 -AllowPartialDownload`** and clearer missing-asset guidance (a full release
  verification still requires every checksum-listed asset).
- **CI regression coverage:** real WPF sample-app launch/context persistence test and a full
  WPF-shell-workflow test against the real WPF sample apps (`WT-04-09`), so the earlier
  headless-only coverage gap is closed.
- The desktop bundle now also contains the headless shell for the packaged self-test.

## Clean-machine verification (2026-11-16, physical Windows 11 reference laptop)

- All v1.0.2 assets independently verified: **VERIFY PASS** (desktop, headless, source, SPDX SBOM).
- Packaged headless self-test: exit 0, `status=succeeded`, **steps=6**, diagnostics bundle written.
- Packaged GUI run: WPF Shell + pre-filled reference command produced **6/6 Succeeded** steps; the
  three real WPF sample windows stayed open with typed context; private summary and Inspector
  available (sanitized screenshot in
  [`docs/testing/evidence/2026-11-16-windows11-v1.0.2-desktop-bundle.md`](../testing/evidence/2026-11-16-windows11-v1.0.2-desktop-bundle.md)).
- The earlier v1.0.1 transient observation of sample windows closing did not reproduce; the added
  diagnostics/self-test make any recurrence inspectable.

## Verification

- Required CI lanes remain the gate; the Windows UI lane executes the new real-WPF-sample tests.
- Release assets include the updated `windows-x64-desktop.zip`, headless binaries, source snapshot,
  SPDX SBOM and checksums; verify with `tools/release/Verify-Release.ps1` (expect `VERIFY PASS`).
- Operator follow-up: run `Test-AetherWorkflow.ps1` from the extracted bundle and share the
  `diagnostics/` result and `Collect-Diagnostics.ps1` ZIP if the packaged workflow still fails.

## Remaining gap-assessment items

G-02/G-04/G-06/G-10 (measurement/coverage), G-07/G-13 (accepted deviations) and the formal scope
decisions ADR-009/ADR-010 are unchanged. This release improves diagnostics and regression coverage;
it does not claim those measurement gaps are closed.
