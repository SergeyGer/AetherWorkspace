# v1.1–v1.5 execution plan (demo, interoperability, hybrid AI)

**Source of truth:** *AetherWorkspace — Demo and Development Execution Specification v1.1–v1.5*
(`AW-DP-001`, revision 1.0, 2026-11-16) plus the post-v1.0 gap assessment
([`docs/audit/2026-11-16-gap-assessment-response.md`](../audit/2026-11-16-gap-assessment-response.md)).
This page maps every required work item to a GitHub Issue, milestone, dependency and acceptance
gate. Issues are the work units; this document is the reviewed plan index.

## 1. Execution architecture (non-negotiable)

- **Remote engineering plane:** DeepSeek Harness on Hetzner Linux writes code, fixtures, scripts,
  tests, Issue/Wiki updates and PRs; runs Linux suites and reviews GitHub CI. It cannot operate the
  Windows laptop desktop, run OBS or record the screen.
- **Local interactive plane:** the physical Windows 11 reference laptop executes GUI automation,
  OBS/FFmpeg capture and evidence collection under an approved full SHA, in an unlocked session.
  No inbound remote-control service, no public self-hosted runner, no unattended unlock.
- **GitHub:** review/PR/CI and sanitized evidence hand-off only; raw desktop media and raw logs stay
  local. Publication requires human review.

## 5. Evidence and CI strategy

- **Linux CI (portable):** catalog/schema/fixture purity, contextRef mapping, echo suppression,
  dedupe/ordering, plan/authorization and redaction unit tests; TRX + commit SHA.
- **Windows CI:** WPF build, named-pipe GUI E2E including click-driven Watchlist→Risk→Chart
  synchronization, packaged desktop build, real WPF sample-window tests; TRX + sanitized evidence.
- **Physical Windows 11 (local):** native multi-process launch, real PIDs, tiling geometry, ticker
  switches, focus/keyboard, 100% DPI baseline, capture health and media QA; approved SHA +
  local run manifest + operator PASS.
- **Recording plane:** local OBS/FFmpeg only; no remote execution; no raw media/credentials in the
  public repository; publication after human review.
