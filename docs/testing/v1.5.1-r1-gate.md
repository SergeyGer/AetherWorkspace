# v1.5.1 — Windows 11 R1 release gate runbook

Operator-owned physical verification for **v1.5.1 Workspace UX & AI Command Center**. This run must
happen on the interactive, unlocked Windows 11 reference laptop; the Linux Hetzner workspace has no
remote desktop control and must never be presumed to have performed this run.

**No v1.5.1 PASS is claimed until the sanitized gate artifacts are returned and reviewed.**

## 1. Trust the revision

1. Merge the v1.5.1 PR and wait for all required GitHub CI jobs to pass.
2. In the trusted clone, fetch `main` and choose the reviewed full 40-hex SHA:
   ```powershell
   cd C:\AetherWorkspace\trusted
   git fetch origin
   git checkout origin/main
   $sha = (git rev-parse HEAD).Trim()
   if ($sha -notmatch '^[0-9a-f]{40}$') { throw 'not a full SHA' }
   Set-Content -LiteralPath C:\AetherWorkspace\approved-revision.txt -Value $sha
   ```
3. Confirm the laptop is unlocked, on AC power, with the expected displays and WebView2 Runtime.
4. Do not edit product code locally for the physical run. Use the same reviewed SHA as CI.

## 2. Automated physical gate

The gate runs the release-full suite, exports the WT ledger, runs the 100-cycle UI measurement and
(optionally) captures the v1.5.1 hero. The release-full profile includes `Category=ReferenceDesktop`,
which now contains:

- existing WT-04/WT-05 reference-desktop tests;
- **`CommandCenterDesktopTests.WebView2DemoPresetRunsStrictValidatedWorkspaceThroughTheShell`** —
  drives the real Shell through the WebView2 preset, verifies Strict selection and the presence of
  Watchlist + Risk + the independent WebView2 chart window;
- existing layout, persistence, WebView2 bridge/fallback tests.

### Gate + hero capture

```powershell
pwsh -NoProfile -File C:\AetherWorkspace\trusted\tools\windows-test\Run-PhysicalReleaseGate.ps1 `
  -RepoRoot C:\AetherWorkspace\trusted `
  -ApprovedRevisionFile C:\AetherWorkspace\approved-revision.txt `
  -ConfigPath C:\AetherWorkspace\automation\test-config.json `
  -EnvironmentFile C:\AetherWorkspace\trusted\.env `
  -CaptureScenarios V151 `
  -PromptObsPassword
```

- `-CaptureScenarios V151` is the v1.5.1 hero: AI Command Center → Strict preset → deterministic
  validation → WPF Watchlist + Risk + WebView2 chart. It is intentionally deterministic so the
  captured provenance is truthfully `deterministic-grammar, model=False`; Track β/LLM planning remains
  covered by its own tests, not conflated with this scene.
- If OBS is unavailable, run the same gate with `-SkipCapture`; the release gate is then automation
  only and the video phase remains open.
- If `-UiCycles` is omitted it defaults to 100. `-SkipMeasurements` skips only the UI measurement;
  release-full and WT ledger always run.

### Key artifacts to return

Copy the **sanitized** items from the gate directory (`C:\AetherWorkspace\results\physical-gate-*`):

1. `gate-summary.json` — overall and per-step states;
2. `run-result.json` and `environment-manifest.json`;
3. `wt-ledger.json` / `wt-ledger.md`;
4. `ui-responsiveness-*.json`;
5. `capture-V151-*.json`, `video-build-V151*.json`, `video-validation.json` if captured;
6. the validated MP4/GIF for review (raw media stays local).

Do not return screenshots with personal windows, terminal secrets, provider keys or unrelated data.

## 3. Manual UI checks (operator)

After the automated gate, use the same approved build for a short human pass:

- Application catalog lists the registered WPF + WebView2 apps with health status.
- **WebView2 demo preset** loads Strict mode and the reference instruction.
- **Run Instruction** opens Watchlist + Risk + WebView2 without overlap.
- **Launch Selected**, per-app **Launch/Focus/Stop/Restart** work through the broker (no parallel launcher).
- **Strict** with an unselected app shows the denial (`plan.selection.app_not_selected`) and no side effects.
- New/Save/Duplicate/Delete/Saved templates survive a Shell restart under `%LOCALAPPDATA%\AetherWorkspace\instructions`.
- At 125%/150% DPI the Command Center and app grid remain usable; record any manual-only limitation
  instead of claiming PASS.

## 4. Evidence disposition

- Automation PASS + physical R1 PASS + media review are required before a v1.5.1 release/tag.
- A failed preflight is `SKIPPED_*`/`INCONCLUSIVE`, never PASS.
- Manual WT-05 rows remain the accepted known limitation from v1.x; do not convert them to PASS.
- Record the gate run id, approved SHA, OS/build, WebView2 Runtime version, display configuration and
  exact commands in `docs/testing/evidence/` after review.
- Video publication requires explicit operator approval; do not upload automatically.
