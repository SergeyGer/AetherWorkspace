# v1.5 extension decisions — Electron NO-GO and bounded FDC3 (2026-11-18)

Decision evidence for AW-063 (#91) and AW-064 (#92). No Electron dependency/prototype and no broader
FDC3 runtime surface were added.

## AW-063 Electron adapter — NO-GO

- ADR-012 records the decision with measured footprint and structural IPC comparison.
- Measured upstream Electron v45.3.4 Windows x64 release ZIP: **158,262,038 bytes (~151 MiB)**;
  local WPF sample build ≈1.9 MiB, WebView2 chart host build ≈4.0 MiB, complete Windows desktop bundle
  (v1.1.0 release asset) ≈3.6 MiB.
- The existing v1.2 WebView2 host already proves independent-process typed-context synchronization on
  Windows CI; a duplicate Electron PoC would add Chromium/Node runtime, main↔renderer/preload IPC,
  packaging/update and security-review burden without new interop evidence.
- No Electron dependency, executable, packaging or release-blocking change is present. Revisit only
  with a specific unmet product requirement and approved PoC/security review.
- Documented under `prototypes/electron/README.md`; no performance/memory claim is made without a PoC.

## AW-064 broader FDC3 surface — keep bounded subset

- ADR-013 keeps the existing subset: single `default` channel; only `ViewInstrument`, `ViewAnalysis`,
  `ViewChart`; only `fdc3.instrument`, `fdc3.organization` and project-specific `aether.exposure`;
  no directory federation/Desktop Agent Bridge; no conformance or external interop claim beyond the
  recorded Sail DACP checks.
- `docs/fdc3/supported-subset.md` now has an explicit rejected-surface table.
- New `tests/Aether.Fdc3.Tests/BroadenedSurfaceRejectionTests.cs` covers unknown broader intents,
  non-default channel subscribe/publish denial, and snapshot projection restricted to the bounded
  intent/context/channel sets.
- Existing official-schema/DACP interop tests remain; no conformance wording changed.
