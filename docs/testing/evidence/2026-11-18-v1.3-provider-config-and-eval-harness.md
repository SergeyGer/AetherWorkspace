# v1.3 provider configuration + evaluation harness — 2026-11-18 (CI evidence)

Implementation evidence for the v1.3 hybrid-AI increment. All values below are measured by the
committed CI deterministic baseline or the unit/E2E tests; **no live model quality/latency/cost
numbers are claimed here** and none are fabricated.

## Scope implemented

- **AW-059 per-capability providers (#87):** `ModelProviderCatalog` resolves
  `AETHER_PLANNER_PROVIDER` and `AETHER_SUMMARY_PROVIDER` independently with
  `AETHER_MODEL_PROVIDER` fallback. Supported providers: OpenAI-compatible, Gemini, local/Ollama,
  deterministic. Validation is fail-closed: unsupported brand, non-HTTPS cloud endpoint,
  non-loopback local endpoint or empty model id produces `provider.config_invalid`; the router falls
  back deterministically and the actual planner/provider is reported truthfully.
- **AW-067 local profile + credential lifecycle (#95):** supported profile `qwen2.5:7b` (Ollama,
  Apache-2.0, pinned model/layer digests, hardware guidance), `LocalModelPlanProvider`, optional
  Windows Credential Manager secret source, environment/.env default, timeout/failure tests.
- **AW-060 gold-corpus evaluation (#88):** 120 labelled synthetic items (80 canonical-plan,
  40 adversarial negatives), deterministic generator, semantic plan/denial accuracy, repeated
  trials, p50/p95/p99 latency, labelled token/cost estimates, hardware fingerprint, explicit
  TTFT-unavailable deviation.

  local-profile default.

  plan references.

  store selection, Windows-only guard, no value echo.
- `tests/Aether.E2E.Tests/ProviderConfigurationE2ETests.cs` — invalid provider falls back

  reported without network I/O.
- `tests/Aether.AI.Tests/ModelRouterTests.cs` — existing classification/consent/egress routing tests
