## AW-034 — review-only contract generation assistant

- Deterministic, bounded templates in `Aether.Contracts.Studio` for registry entries, proto3
  message snippets and JSON Schema drafts; identifiers/capabilities/context types/classifications
  constrained to documented values.
- Drafts are explicitly **untrusted envelopes** (`Untrusted=true`, status `Untrusted`) stored in a
  staging directory; they cannot mutate the active registry or execute anything.
- `tools/Aether.ContractStudio` CLI: `generate`, `review` (never writes), `apply --confirm`
  (validates first, then atomic write of the reviewed target only).

## AW-035 — validation before acceptance

- Classified change detection vs the active registry: new app/capability = non-breaking; removed
  capability/context-type/classification, reduced `maxInstances` or changed launch definition =
  **breaking** and rejected by `apply`.
- Forbidden target paths (`.git`, `bin`, `obj`, `.ssh`, `secrets`, `node_modules`, `.env`) and
  target extension mismatches produce actionable diagnostics.
- Negative tests cover breaking classifications, forbidden/wrong paths, traversal rejection,
  missing `--confirm`, and validation-before-write.

## Known boundaries

- No protoc/compiler execution by design; proto drafts are bounded snippets validated structurally,
  not compiled (AW-035 explicitly excludes auto-compilation).
- No cloud transmission or customer data; generation uses local templates only.
