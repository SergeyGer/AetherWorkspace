# v1.4 privacy-gateway decision — reject sanitized INTERNAL cloud routing (2026-11-18)

This is the security-gate evidence for AW-061 (#89) and AW-062 (#90). The decision is **reject** for
the v1.x line; no INTERNAL cloud route or token-vault provider integration was enabled.

## Decision

- [ADR-011](../../adr/ADR-011-reject-sanitized-internal-cloud-routing.md) records **REJECT**:
  cloud remains **PUBLIC-only** for v1.x. The end-to-end classifier→vault→egress→de-mask chain was
  not implemented; the rule-based detector has no PII precision/recall or NER guarantee; provider
  logging/retention and placeholder-leak/de-mask failure risks are unacceptable without independent
  security review.
- `PolicyEngine.SanitizedInternalCloudRoutingEnabled` is a compile-time **false** hard gate.
  A custom policy document setting `AllowSanitizedInternal=true` and a caller claiming
  `SanitizationReviewed=true` still gets `policy.cloud.denied_by_default`; this latent path cannot
  be enabled in a v1.x build.
- `SessionTokenVault` remains a local, unit-tested redaction primitive only. A repository architecture
  guard proves it is not referenced by `src/Aether.AI` provider code.
- Re-enabling requires a superseding ADR, independent review, approved DLP/classifier with measured
  false-negative behaviour, provider data-handling assessment, before/after sanitization tests,
  expiry/cancel/failure tests and placeholder-leak prevention evidence.

## Tests/evidence

- `tests/Aether.Security.Tests/SanitizedInternalRejectionTests.cs`:

  never invokes the transport for sanitized INTERNAL; RESTRICTED/UNKNOWN transport calls = 0.
- Updated `tests/Aether.Security.Tests/PolicyEngineTests.cs` to assert the hard rejection.
- `tests/Aether.Contracts.Tests/PrivacyGatewayRejectionTests.cs`: PUBLIC-only default matrix and
  no `SessionTokenVault` wiring in `src/Aether.AI`.
- Existing egress/denial/classification suites remain green.
- Threat model, limitations, ADR index, Wiki and release/status docs updated to state the rejection.

## Non-claims

- No zero-leak, anonymization, PII-detection or sanitized-INTERNAL cloud claim is made.
- The vault is not a guarantee and is not wired into any provider path.
