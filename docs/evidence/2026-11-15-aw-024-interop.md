# Evidence record — AW-024 external FDC3 interop increment (2026-11-15)

Complements v0.3.0 (`docs/evidence/2026-11-15-v0.3-fdc3-reliability.md`).

## Delivered

- Vendored official FDC3 3.0 context JSON Schemas (`finos/FDC3` commit
  `c6adda7a1f66d97d03809343852a4bfc0806f859`, Apache-2.0) with provenance/licence fixtures:
  `tests/fixtures/fdc3/official/`.
- Independent external validator `tools/fdc3-interop/validate_fdc3.py` (Python
  `jsonschema`, unlike the product's .NET validator) covering fixture, trusted-catalog and
  metadata-projection payloads; machine-readable report emitted in CI.
- Product contract tests `tests/Aether.Fdc3.Tests/OfficialSchemaInteropTests.cs`
  (official schema validation + pinned provenance/licence assertions + metadata projection).
- `Aether.Contracts.Fdc3.Fdc3MetadataProjection`: broker provenance → FDC3 3.0
  `ContextMetadata` shape (source app/instance, ISO-8601 timestamp, traceId).
- `docs/fdc3/interop-report.md`: conformance landscape research (FDC3 3.0 with three
  conforming desktop agents; JS Desktop Agent API conformance framework; experimental DACP),
  what was validated, deviation register and the DACP/Sail plan for the next increment.
- CI Linux job runs the independent Python validator on every build.

## Results

- Independent validator: **7/7 payloads valid**, schema commit `c6adda7a1f66`, no validated
  payload deviations.
- FDC3 test project: **20/20 tests** (15 earlier + 5 new interop tests).
- No FDC3 conformance claim is made; third-party runtime interop remains open.
