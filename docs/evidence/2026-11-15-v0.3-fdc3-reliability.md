# Evidence record — v0.3 bounded FDC3 interoperability + reliability closure (2026-11-15)

Third development step. Scope: bounded FDC3 interoperability (AW-021…AW-024) and closure of
the remaining v0.2 evidence gaps (AW-018 Windows benchmark, AW-019 OS-level blocked egress),
plus UI automation, SBOM/release publishing and `.env` provider template.

## Implemented

| Item | Implementation |
|---|---|
| FDC3 contexts (AW-022) | `fdc3.instrument` + `fdc3.organization` typed payloads (`src/Aether.Contracts/Models/Contexts`, `src/Aether.Contracts/Fdc3`), catalog validation, protobuf envelope delivery on the single `default` channel with provenance. |
| Intent resolution (AW-023) | `ResolveIntent` RPC + `intent.resolve` capability; `IntentRouter` maps `ViewInstrument`/`ViewAnalysis`/`ViewChart` to apps that declare the intent and accept the required context type; preferred targets must be approved; unknown intent / context mismatch / unapproved target return structured denials. App-directory subset exposed via `GetSnapshot` intents. |
| Subset matrix (AW-021) | `docs/fdc3/supported-subset.md` updated to the implemented bounded subset and unsupported surfaces; no conformance claim. |
| Contract/interop evidence (AW-024, partial) | Fixtures `tests/fixtures/fdc3/*`, dedicated `tests/Aether.Fdc3.Tests` (context contracts, intent matrix, capability denials), multi-process `Fdc3E2ETests`. Independent FDC3 implementation interop not performed. |
| Windows IPC benchmark (AW-018) | Windows CI runs `Aether.IpcBench` over **named pipes**; raw output uploaded as CI artifact. |
| OS-level blocked egress (AW-019) | `scripts/egress-blocked-check.sh` runs the reference workflow inside an isolated Linux network namespace with no external connectivity; `scripts/egress-blocked-check.ps1` blocks outbound .NET traffic via Windows Firewall and runs the named-pipe demo. Both are CI steps and assert the demo's own `externalAttempts = 0` claim. |
| UI automation | `tests/Aether.Shell.UiTests` (FlaUI/UIA3, Windows-only, not in the main solution): shell smoke (window/controls/backend mode) and restricted reference workflow via the Run button, with trace/summary assertions. Runs in a dedicated Windows CI job. |
| `.env` template | `.env.example` for OpenAI/Gemini/local providers; `.env` is git-ignored and loaded only explicitly with `--env-file` (in-memory secret provider, no process-env mutation). Parser tests in `DotEnvFileTests`. |
| Publishing | GitHub Releases per milestone, release workflow on `v*` tags (binaries/source/SBOM/checksums), SBOM generation in CI, branch protection ruleset, issue dependency links/assignees and a Kanban project. |

## Test totals

Main suite: **354 tests** — contract 41, security 50, execution 140 (incl. 100 unsafe-plan
cases), AI 27, broker 56, workflow 9, FDC3 15, E2E 16. Additional Windows-only WPF UI tests:
2 (FlaUI). Release build: 0 warnings / 0 errors.

## Reproduce

```bash
dotnet build AetherWorkspace.slnx -c Release
dotnet test  AetherWorkspace.slnx -c Release
./scripts/demo.sh
./scripts/egress-blocked-check.sh        # Linux OS-level blocked-egress evidence
```

  behaviour, not visual arrangement correctness).
- Real OpenAI/Gemini/local model inference and evaluation (v0.4).
