# v1.5.1 hero video — operator runbook

The v1.5.1 hero shows the **AI Command Center** as the entry point: instruction + explicit application
scope, deterministic validation, then real WPF Watchlist/Risk plus the independent WebView2 chart.
It must show only genuine state and truthful provenance. Raw media and provider credentials stay local.

## Scenario

- Scenario id: `V151` (deterministic; `usedModel=false`).
- Scenes emitted by `tests/Aether.Desktop.E2E.Tests/DesktopGuiE2ETests.CaptureReferenceDemoScenario`:
  `shell-ready`, `command-center-preset`, `workflow-started`, `workflow-succeeded`, `demo-layout`,
  `sample-windows`, ticker scenes, inspector, completion.
- Captions live in `tools/demo/demo-scenes.json`; do not invent latency or model claims.

## Local prerequisites

- Windows 11 x64, unlocked interactive session, AC power, clean desktop/notifications.
- OBS with WebSocket bound to `127.0.0.1`; FFmpeg; WebView2 Evergreen Runtime.
- Approved full SHA in `C:\AetherWorkspace\approved-revision.txt`.
- Optional `.env` for Track B only; V151 needs no provider key.

## Capture

Use the gate command in
[`docs/testing/v1.5.1-r1-gate.md`](../testing/v1.5.1-r1-gate.md) with `-CaptureScenarios V151`.
`Record-Demo.ps1` accepts `V151` and drives the real Shell by AutomationIds; it does not use a fake
window or a pre-recorded desktop.

## Review before publication

1. Inspect the MP4 at normal speed: no taskbar/personal windows, no secrets, WebView2 window visibly
   present, instruction and Strict mode readable.
2. Confirm manifest `planner=deterministic-grammar`, `usedModel=false`, approved SHA, trace id, PIDs.
3. `Validate-Video.ps1` must PASS (codec, 60–95 s, dimensions, black frames, GIF size, hashes).
4. Human approval is required before publishing to YouTube/GitHub; record the approved URL/asset
   hashes and publication decision in the v1.5.1 release notes.
5. If the capture fails, keep it local and re-run after fixing the cause; never relabel a failed take.
