# v1.5.1 hero video — operator runbook

The v1.5.1 hero shows the **AI Command Center** as the entry point: instruction + explicit application
scope, deterministic validation, then real WPF Watchlist/Risk plus the independent WebView2 chart.
It must show only genuine state and truthful provenance. Raw media and provider credentials stay local.

## Scenario

- Scenario id: `V151` (deterministic; `usedModel=false`).
- Scenes emitted by `tests/Aether.Desktop.E2E.Tests/DesktopGuiE2ETests.CaptureReferenceDemoScenario`:
  `shell-ready`, `command-center-preset`, `instruction-typed`, `workflow-started`,
  `workflow-succeeded`, `demo-layout`, `sample-windows`, ticker scenes, completion.
- **No burned-in captions.** The capture starts with an empty Instruction (demo-only
  `AETHER_DEMO_EMPTY_INSTRUCTION=1`), types it progressively, then the Shell is minimized and
  the three WPF/WebView2 windows are arranged side-by-side across the full work area before the ticker
  scene. All explanation is in the continuous synthetic English voiceover
  `docs/demo/media/narration-v151.mp3` (script: `docs/demo/narration-script-v151.md`).
- Do not invent latency, provider, compliance or PII claims.

## Local prerequisites

- Windows 11 x64, unlocked interactive session, AC power, clean desktop/notifications.
- OBS with WebSocket bound to `127.0.0.1`; FFmpeg; WebView2 Evergreen Runtime.
- Approved full SHA in `C:\AetherWorkspace\approved-revision.txt`.
- Optional `.env` for Track B only; V151 needs no provider key.

## Capture

After the demo-tooling fix is merged, use the new reviewed SHA and the gate command in
[`docs/testing/v1.5.1-r1-gate.md`](../testing/v1.5.1-r1-gate.md) with `-CaptureScenarios V151`.
`Record-Demo.ps1` accepts `V151` and drives the real Shell by AutomationIds; it does not use a fake
window or a pre-recorded desktop. The capture test minimizes the command surface before the app
scene, so the reviewer sees all three windows without the Shell covering them.

If only the video changed (product code otherwise identical to the approved physical-gate SHA), the
release notes must state the physical-gate SHA and the video-capture SHA explicitly; do not silently
substitute media from a different revision.

## Review before publication

1. Inspect the MP4 at normal speed: no taskbar/personal windows, no secrets, no burned-in captions;
   progressive instruction typing visible; all three WPF/WebView2 windows fully visible after the
   Shell is minimized; WebView2 window visibly present; Strict mode readable.
2. Confirm manifest `planner=deterministic-grammar`, `usedModel=false`, approved SHA, trace id, PIDs.
3. `Validate-Video.ps1` must PASS (codec, 60–95 s, dimensions, black frames, GIF size, hashes).
4. Human approval is required before publishing to YouTube/GitHub; record the approved URL/asset
   hashes and publication decision in the v1.5.1 release notes.
5. If the capture fails, keep it local and re-run after fixing the cause; never relabel a failed take.
